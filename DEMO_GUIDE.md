# Rumi demo guide: three people, everyday situations

**Updated October 29, 2026 · Presenter edition**

Use this guide to show how Rumi helps someone understand their information, talk through a problem and choose a useful next step. Each story includes the person to select, buttons to press, words to type or say, and the result to look for.

**Start here:** use the simplified **Rumi iPhone** app or the main page of the matching **Web** app. The older Web experience lives at `/original` and has different screens.

## What the presenter should know

Use these three labels when introducing a feature:

- **AI conversation:** A reply generated for the current message. Chat uses Sonnet 5.5. The iPhone demo’s live voice uses GPT-Realtime 2.
- **Local demo action:** A reviewed change saved with the selected fictional member, such as a goal, recipe or grocery list.
- **Connected-service extension:** A separate flow requiring an authorized account and a working service. Portal actions, shared iMessage continuity and telephone calls belong here.

AI responses vary. Treat the “look for” notes as presentation checks, rather than promises of exact wording. If a check fails, move to the fallback and record the issue.

**Simple opening line:** “We’ll use three fictional people. You’ll see real AI conversation, sample health records and practice actions that the person reviews.”

**Important boundary:** Medical decisions belong with the care team. Demo confirmations update local practice data. Real account saves and external actions are clearly separated in the appendix.

## Setup and basic controls

### Before the audience arrives

1. Open the app on the device or browser you will present from.
2. Confirm internet access. Ask the project owner to check AI access for this build.
3. Try one short chat message and, if presenting voice, one microphone exchange.
4. For recipe research, prepare a specific public recipe link from MyPlate, Diabetes Food Hub, Budget Bytes or EatingWell. Open it in the reader during rehearsal.
5. Use fictional information throughout. Keep passwords, verification codes and private account screens out of screen sharing.
6. For the connected-service appendix, get the owner’s explicit approval and rehearse with their authorized test account first.

### Enter and reset

1. Choose **Explore a demo** on the welcome screen.
2. Select **Primary demo member**.
3. Choose **Start demo** on Web or **Start demo with Primary** on iPhone.
4. Open the three-line menu → **Reset this demo member** → confirm.
5. Repeat the reset for Maria and Tom if you want fresh starting points, then return to Primary.

Reset returns the chosen person to their starting sample records and seeded goals. Exiting preserves local changes. Each browser or device keeps its own demo state.

### Send a message

1. Paste one quoted message from this guide into the message box.
2. Press the up-arrow **Send** button.
3. On Web, the first AI request opens a processing notice. Choose **Allow AI processing** if you agree, then press **Send again**.
4. Wait for the reply before sending the next message.
5. Use **Stop** on iPhone or the stop button in the Web composer to end a pending reply.

### Find a screen

On **iPhone**, scroll below the conversation for shortcuts. Use the back button to return to chat. The three-line menu contains reset and exit.

On **Web**, use the three-line menu. Close a panel using its **X** to return to chat.

Common destinations:

- Charts: **Insights walkthrough · Charts in chat** on iPhone; **Insights walkthrough** on Web.
- Goals: **Saved goals & demo memory** on iPhone; **Goals & memory** on Web.
- Services: **Demo services · Instagram, Instacart & Uber** on iPhone; **Rumi Works** on Web.
- Public sources: **Browse public recipes with Rumi** on iPhone; **Rumi Works → Read a public recipe source** on Web.
- Outreach: **Preview calls & messages** on iPhone; **Outreach rehearsal** on Web.

## Primary member: labs, appointments and medicine questions

### A1. Turn a normal question into insight cards

**Use:** Primary. **Where:** Chat, iPhone or Web.

1. Select Primary and send:

   > Show my A1c and eGFR side by side, and also my latest LDL.

2. Look for cards inside the conversation. The label explains that AI selected the query and the app calculated the facts.
3. Check the values against Primary’s profile above.
4. Choose **All** on each chart to include older sample results.
5. On iPhone, drag along the chart. On Web, move the pointer over it.
6. Expand **Accessible values & sample dates**. Read one date and value aloud. Web also offers selectable value rows.
7. Try **30d** and **90d**, then return to **All**. A short window can have few or zero observations.

**Look for:** Separate dates and units, a neutral description of changes, and charts that stay inside chat. Side-by-side charts show two measures; they do not establish a cause or relationship.

**Say:** “Rumi understands which information I’m asking for. The app calculates the numbers, so the chart comes from the sample records.”

### A2. Ask for more data than exists

1. Send:

   > Show my last 4 A1c results. If fewer exist, show only those available.

2. Check that Primary’s two available A1c results are shown.
3. Send:

   > Compare my A1c with people like me and show my CGM time in range.

4. Look for an explanation of the missing comparison group and continuous glucose monitor data.
5. For another missing-data example, send:

   > Show my latest BMI.

**Look for:** An honest unavailable result. BMI needs information this profile lacks; a plausible-looking number would be a failed presentation check.

**Fallback for A1–A2:** Open **Insights walkthrough** → **Calculated preview · No AI request**. Describe it as the chart preview. The buttons in **Ask Rumi · Live Sonnet 5.5** send actual AI requests.

### A3. Prepare for an appointment in a hurry

1. After a data answer, choose **Yes, talk about my goal** on iPhone or **Yes, please** on Web.
2. Read the short question about what you want to work toward. This invitation and question are supplied by the app.
3. Send:

   > For this practice visit, I’m seeing my PCP next week. I have thirty seconds now. Give me one question to take about my repeat labs.

4. Read the short draft aloud. PCP means the regular primary care clinician.
5. Send:

   > I have more time now. Help me prepare three questions about my kidney results, cholesterol plan and personal targets.

6. Look for questions tied to this profile, suitable to take to the clinician.
7. Send:

   > I tend to leave visits unsure what happens next. Give me a sentence I can say before I leave.

8. Choose a question you like and save it using the **Goals** steps later in this guide.

**Look for:** A short first response, a more detailed second response and a usable request for written next steps. The future visit is your role-play detail; this flow prepares for it rather than booking it.

**Say:** “The help changes with the time I have. I leave with something I can actually say.”

### A4. Make a medicine list and raise a cost concern

1. Send:

   > Help me make a medicine list for my visit from this demo record. Mark what I need to confirm with my pharmacist.

2. Check the three supplied medicine names and doses. Look for frequency and actual use to remain questions.
3. Send:

   > In this practice scenario, cost makes it hard to refill a medicine. Help me write one question for the pharmacist.

4. Look for a practical question about affordable options or coverage, with any medicine change left for the pharmacist or prescriber.
5. Open **Care follow-ups** using the steps under **Care follow-ups, rides and outreach rehearsals** to show how an exact refill question is reviewed.

**Say:** “Rumi helps prepare the conversation, using what’s known and asking about what’s missing.”

## Maria: medication routines, symptoms and meals

### B1. Find the real obstacle to following a medicine routine

**Use:** Maria. **Where:** Chat; repeat a short version in iPhone voice.

1. Switch to **Maria Alvarez**. Keep her care story at baseline for this conversation.
2. Send:

   > For this practice scenario, I follow my prescribed medicine plan, but on busy evenings I lose track of whether I’ve done it. Help me think through a reminder.

3. If Rumi asks what interrupts the routine, answer:

   > I’m getting dinner ready and helping my family. I want a simple way to mark it as done.

4. Look for a practical cue or checklist fitted to the existing prescribed plan.
5. Send:

   > A tick on a paper checklist sounds manageable. Help me phrase that as a goal for review.

6. Follow **Goals** to review and save the chosen wording.
7. To show the missed-dose boundary, send:

   > Separate practice question: I’m unsure whether I missed a dose. Help me write the question for my pharmacist.

**Look for:** One useful question at a time, help with tracking the routine and a pharmacist question for uncertainty about a dose. Medicine timing, dose and storage stay with the prescribed instructions. The demo has no dose-taking log, adherence score or automatic medication reminder delivery.

**Say:** “We found the practical snag: keeping track during a busy evening.”

### B2. Offer symptom support that fits the moment

**Use:** Maria. These are spoken or typed fictional scenarios. If someone describes a real current concern, stop the presentation and follow appropriate care guidance.

1. Send:

   > Fictional practice scenario: I’ve felt mild nausea since starting a medicine. I can keep fluids down and have no severe pain. I want help describing it to my pharmacist.

2. Answer any essential question using only details supplied in the role-play. “I don’t have that detail” is a valid answer.
3. Send:

   > Draft a short message with when it began, what I noticed and the questions I should ask.

4. Look for a copyable draft, with blanks or questions for missing facts.
5. For general education, send:

   > In plain English, what can GLP-1 medicines change about appetite, and what should I discuss with my prescriber?

6. Look for a concise explanation, acknowledgement that experiences vary, and questions that fit the situation.
7. **Optional safety check, last:** Send:

   > Fictional safety rehearsal: someone has severe persistent abdominal pain and cannot keep fluids down. What should happen now?

8. Look for urgent professional assessment to take priority over routine coaching. Finish this scenario, then switch or reset before continuing a lighthearted meal story.

**Say:** “The response follows the concern. A routine question gets practical help; a serious warning sign gets urgent attention.”

### B3. Save an Instagram-style recipe, then review an Instacart-style list

**Use:** Maria. Available to Primary and Tom too. **Type:** Seeded recipe + local reviewed actions, with an optional AI discussion.

1. Open **Demo services · Instagram, Instacart & Uber** on iPhone, or **Rumi Works** on Web.
2. Choose **Instagram**.
3. Open or scroll to **Lemon chickpea & rice bowl**. The creator is **weekday.table.demo**. The feed and creator are invented examples.
4. Read the sample ingredients. Choose **Review saving this demo recipe** on iPhone or **Review saving this recipe** on Web.
5. Read the review, then confirm the local recipe save.
6. Return to the recipe. Look for **Saved to demo recipes**. This is the visible saved marker in this flow; it is separate from a real Instagram Saved collection.
7. **iPhone AI step:** Choose **Discuss this sample with Rumi**, then return to chat to see the reply. On Web, close the panel and type:

   > I’m considering the seeded lemon chickpea and rice bowl in this demo. Dinner is rushed. Help me plan one preparation step, using the sample recipe rather than claiming a live Instagram lookup.

8. Return to the recipe and open its grocery comparison. On Web choose **Compare pantry & groceries**.
9. Read **Fictional pantry**, **Recipe needs** and the missing ingredients.
10. Check the example quantities:
    - **iPhone:** Pantry covers chickpeas, rice and oil. For this bowl, the missing items are **1 whole lemon** and **100 g spinach**.

**Say:** “A saved dinner idea becomes a short, reviewed grocery list.”

## Tom: barriers, goals, nudging and listening

### C1. Show COM-B through an ordinary conversation

**COM-B in plain English:** Can I do it? Does my day allow it? Do I want to do it? The presenter can use the name; Rumi should talk like a person, rather than label someone with a framework.

**Use:** Tom. **Where:** Chat, with an optional iPhone voice repeat.

1. Switch to **Tom Becker** and send:

   > In this practice scenario, my clinician has cleared a short lunch walk. I want to do it, but meetings take over. Help me find a version that fits.

2. Let Rumi respond. If it asks about your day, answer:

   > Lunch starts at a different time every day, but I always close my laptop before eating.

3. Ask for a specific plan:

   > Help me use closing my laptop as the cue. I want a small version for busy days too.

4. Look for the plan to fit the stated cue and your existing clinician guidance. Choose the amount yourself if asked.
5. Show a different obstacle:

   > The bigger problem is dinner. I have basic ingredients, a microwave and a tight budget. I’m unsure what I can make.

6. Look for practical help with knowledge, equipment and cost.
7. Show mixed feelings:

   > I like the idea of cooking, but evenings are my only quiet time. I’m not ready to make it a goal.

8. Look for Rumi to reflect both sides and leave the choice with Tom.

**What this demonstrates:** Meetings are an opportunity/time barrier; uncertainty about preparation is a knowledge barrier; protecting quiet time is a reason to hesitate. These are conversation examples, rather than a scored assessment or diagnosis of motivation.

**Say:** “Rumi changes the help when the obstacle changes.”

### C2. Give a useful nudge and handle a difficult week

1. Save a lunch-walk goal using the **Goals** steps below.
2. Send:

   > In this practice week, I did my planned walk on Tuesday and Thursday. Closing my laptop helped me remember.

3. Look for a specific acknowledgement of what helped.
4. Send:

   > This week I missed it because work ran late. I still want the goal. Help me choose a smaller version for a difficult day.

5. Look for one manageable option within the plan Tom described. Choose it or adjust it in your next message.
6. Send:

   > Write one gentle reminder I can put on a note by my laptop.

7. Read the suggested nudge. Put it on a note yourself if desired.
8. Send:

   > Leave food and weight out of this conversation. I want to focus on bedtime instead.

9. Look for a topic change that respects the stated preference.

**Presenter note:** This shows nudging during an active conversation. The reported walks come from your role-play words, not a device. Delivery at a future time requires an enabled reminder or calling service; the local demo provides drafts and outreach rehearsals.

### C3. Listen first, then adapt to a request

1. Send:

   > I’m worn out from looking after everyone. I just want to talk for a moment.

2. Pause after Rumi’s reply. Look for a short acknowledgement and room to continue.
3. Send:

   > Thanks. I have energy for one practical thing now. Help me choose a simple next step for tonight.

4. Look for the response to follow the new request.
5. Try a style correction:

   > Give me the short version today.

6. Look for a shorter answer. A conversational style change is local context unless the person separately approves a supported lasting save.

**Say:** “The person sets the pace. Listening can be the useful response.”

### C4. Use sleep and activity cards to start a conversation

1. Send:

   > Show my steps and sleep side by side over the last 14 days.

2. Inspect both cards, their independent units and the accessible date/value rows.
3. Send:

   > My week felt busy. Help me reflect on what made bedtime easier, using what I tell you rather than guessing from the chart.

4. Add a detail:

   > Putting tomorrow’s work things aside before dinner helped on two evenings.

5. Look for a response grounded in that reported detail. A chart alone supplies no explanation for why something happened.

## Goals: propose, review, save and recall

Use this same sequence with each person. Pick the wording for that story:

- **Primary:** “Write down three questions before my next PCP visit.”
- **Maria:** “Use a paper checklist to track my existing prescribed routine.”
- **Tom:** “Use closing my laptop as the cue for the lunch walk already agreed with my clinician.”

1. Open **Saved goals & demo memory** on iPhone or **Goals & memory** on Web.
2. Enable **Remember within this demo** on iPhone or **Remember my demo goals** on Web.
3. Return to chat. Send “Please propose this as my demo goal for review:” followed by the chosen sentence.
4. On iPhone, choose **Review proposed goal** if offered. On Web, the goals panel may open with the text filled in.
5. Read the exact words. On Web choose **Review exact goal**.
6. Cancel once to demonstrate choice. Reopen the proposal and confirm using **Confirm demo save** on iPhone or **Confirm local goal save** on Web.
7. Reopen the goals screen and point to the saved sentence.
8. Return to chat and ask:

   > What demo goal did I just save? Help me think of one way to make it easier.

9. Switch to another member and inspect their goals. The sentence you added belongs to the original member.
10. Switch back to find it again.

**If a proposal is absent:** Enter the sentence in the goals screen → **Review exact goal** → confirm. This shows the manual review path; describe the AI proposal as incomplete in that attempt.

**Memory controls:** Turning permission off stops future saved-goal recall. The visible chat remains. Reset clears local changes and restores the seeded starting goals. Goals saved here stay on this device/browser; the appendix covers real shared-account goals.

## Voice: present three short conversations

### Start an iPhone voice session

1. Select the intended member. Enable demo memory if using their saved goal.
2. Tap the waveform button by the composer, labelled **Talk to Rumi**.
3. Read the audio-processing notice → **Start live conversation** → allow microphone access if you agree.
4. Wait for **Listening** before speaking.
5. Use one script below. Pause between turns so the audience can hear the response.
6. Try **Mute**, then **Unmute**, then **End**.
7. When an excerpt is available, choose **Review transcript excerpt to remember** → read → **Confirm local demo save** if desired. Memory permission must be enabled.
8. Return to the goals screen’s local receipts to find the retained excerpt.

**What to show:** A real connection state, spoken reply and live captions. The excerpt is displayed conversation text. Saving it retains an excerpt, rather than creating a new goal automatically.

### Voice script 1 — Primary: a rushed appointment question

1. Say: “For this practice visit, I’m seeing my PCP next week. I have thirty seconds. Help me say my main question about the repeat labs.”
2. Listen for a short, usable question.
3. Say: “I’m mostly worried that I’ll forget what to ask.”
4. Listen for help fitted to remembering one question.
5. End. Return to chat to review and save a chosen goal if desired.

### Voice script 2 — Maria: a barrier and a pharmacist question

1. Say: “In this practice scenario, busy evenings make it hard to keep track of my prescribed medicine routine. Help me think through a checklist.”
2. If asked, say: “A paper tick after I follow my existing instructions would suit me.”
3. Say: “Help me phrase a question for my pharmacist about what to do when I’m unsure whether I missed a dose.”
4. Listen for a short draft. Finish with **End**.

### Voice script 3 — Tom: encouragement that fits the day

1. Save Tom’s lunch-walk goal first and enable demo memory.
2. Start voice and say: “Use my saved demo goal as context. Meetings have taken over this week. Help me keep a small version within the plan I described.”
3. Say: “I want help fitting it in, rather than a pep talk.”
4. Listen for a practical response, then end.

**Model distinction:** This iPhone demo voice uses GPT-Realtime 2. The deployed ElevenLabs telephone agent is a separate connection covered in the appendix. Use chat to demonstrate visual insight cards; voice is for the spoken exchange.

### On Web: dictate these scripts into chat

1. Select the member → microphone button.
2. Enable **Allow browser speech processing** if you agree.
3. Choose **Start browser dictation** → speak → **Stop dictation**.
4. Review/edit the transcript → **Place in composer · Not sent** → **Send**.
5. Read the chat reply.

Describe this as **voice input to chat**. Spoken AI replies and a continuous voice conversation are currently iPhone-only in the simplified demo. Browser support and microphone permissions determine dictation availability.

## Insights: charts and helpful ideas in chat

There are two different kinds of insight in the supplied behavior prompt:

1. **Personal sample-data cards:** The visible chart cards from A1, B4 and C4. They contain app-calculated sample facts.
2. **Helpful conversational ideas:** Short explanations or practical suggestions chosen to fit the person’s message. These appear as ordinary AI text; the demo has no separate eight-card gallery or guaranteed graphical card for each topic.

To show the second kind naturally, keep the appropriate member selected and send one message at a time:

- **Primary, A1c basics:** “I’m confused about what an A1c covers compared with a reading from a home meter. Explain it simply.” Look for the difference in time window: roughly three months versus that moment.
- **Primary, medicine costs:** “For this practice scenario, I’m worried about the cost of a brand-name medicine. What could I ask my pharmacist about generics?” Look for a useful question and careful cost wording.
- **Primary, visit preparation:** “I have a visit coming up and often lose my train of thought. Give me one practical idea.” Look for leading with one written question.
- **Primary, visit follow-through:** “I leave visits unsure of the next steps. What could I ask at the end?” Look for asking for written next steps.
- **Maria, medicine list:** “I want to make a list of what I actually take for my pharmacist. Help me start.” Look for medicines, vitamins and supplements to review, with actual use confirmed by the person.
- **Tom, smaller steps:** “The plan feels too big this week. Help me pick a smaller version within the plan I already have.” Look for one manageable option.
- **Tom, routine cues:** “I’ve agreed on a bedtime preparation step. Help me tie it to something I already do.” Look for a cue based on information the person supplies.
- **Any member, optional home BP education:** “General practice question: how should someone set up for a home blood pressure reading?” Look for the approved general setup explanation. This adds no personal BP record or chart to the member.

These cover the prompt’s eight authored insight topics. Pick one or two that fit the story. Asking all eight in one conversation feels like a checklist rather than a useful exchange.

### F4. Recurring, triggered and proactive contact

### If a step stalls

- **AI error:** Check the connection and retry once. Use the labelled calculated preview for charts if needed; record the live request as incomplete.
- **Missing chart points:** Select **All**, or ask for a trend rather than only the latest reading.
- **Goal save disabled:** Enable that member’s demo memory and enter a goal, then review.
- **AI proposal absent:** Use the manual goals field. Record that the proposal did not appear in that attempt.
- **Microphone unavailable:** Use chat. On Web try supported browser dictation, or paste the script.
- **Website blocked:** Try the rehearsed allowed source. Use the seeded recipe journey as the local alternative.
- **Phone number, code or service setup missing:** Skip the live extension. Use the local outreach rehearsal.
- **Save or call outcome uncertain:** Inspect current service state with the owner before sending another request.
